# 风险分档

先依据变更的整体可观察影响分档，再选择流程；不要把一个大改动拆成多个 L1 来规避验证。

| 信号 | 档位 | 处理 |
| --- | --- | --- |
| 仅文案、格式、注释、死链 | L0 | 目视确认并简短记录 |
| 私有实现或测试调整，外部契约不变 | L1 | 写明意图，跑定向验证 |
| Renderer、Electron IPC、WebSocket、串口行为、配置格式、跨模块接口发生可观察变化 | L2 | 完整变更包、场景映射、定向证据、Mode S |
| 真实设备写入、默认安全边界变化、权限/安全升级、发布/迁移、需多阶段自动推进 | L3 | 完整生命周期、Mode L/P、人工闸门 |

### SerialScope 特别规则

- 只读的串口枚举、模拟后端与离线解析不自动构成 L3。
- 将数据发送至真实设备、修改设备配置、自动循环发送、改变写命令默认值或绕过确认提示，按 L3。
- 无法判断设备命令是否有物理影响时，先停止并按 L3 请求人工授权。

每次 L1 以上变更在开始时记录：`risk_tier`、理由、已检查信号与升级条件。
