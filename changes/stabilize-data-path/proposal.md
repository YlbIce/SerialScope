# Proposal: stabilize-data-path

## Why

当前串口工具会为慢速 WebSocket 客户端无限积累待发送消息；Renderer 的连接关闭、手动重连与定时重连会相互叠加；每条收发数据同步重建日志 DOM。这些问题会在高速串口或后端重启时造成内存压力、状态抖动和 UI 卡顿。

## What

- 限制后端单 WebSocket 入站消息与出站队列；过载时丢弃可视化事件并在恢复后通知客户端。
- 校验 WebSocket 命令结构，避免畸形 payload 导致未捕获异常。
- 让 Renderer 重连只有一个定时器和一个当前 socket 所有者，并处理畸形 JSON 消息。
- 将日志渲染合并到动画帧、降低隐藏/可见图表刷新频率，修复统计归零与损坏 profile 的容错。

## Non-goals

- 不改变串口帧边界语义，不实现拆包/粘包解析器。
- 不改变真实设备发送内容、默认自动发送策略或连接真实设备。
- 不拆分 `renderer.js`，不引入前端框架或测试运行器。

## Acceptance

1. 单一慢速客户端的出站缓存具有确定的消息数和字节上限，服务不会无界增长。
2. 非对象 payload、错误字段类型或无效 JSON 命令返回协议错误，而不是导致后端异常退出。
3. 手动连接、旧 socket close 与自动重连不会创建并发重连定时器；非法后端消息不会让 Renderer 消息处理崩溃。
4. 连续日志事件在一个动画帧最多触发一次完整日志重绘；统计值为 0 可正确显示；损坏本地 profile 不阻断启动。

## Risk tier

`L2` — 改变 Renderer 与本地 WebSocket 后端的可观察连接与过载行为，跨越 C++/JavaScript 模块；不执行真实设备写入。若后续改变真实发送默认值或实际设备验证，应升级为 L3。
