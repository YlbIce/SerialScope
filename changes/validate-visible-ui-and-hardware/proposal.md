# Proposal: validate-visible-ui-and-hardware

## Why

现有验证只证明后端、Named Pipe 与 ELTIMA 虚拟端口可运行，不能证明用户实际可见的桌面窗口可操作，也不证明真实串口设备兼容性。

## What

- 修复阻碍 Electron Renderer 使用当前本地 IPC 架构的遗留 WebSocket CSP 配置与文档描述。
- 对可见桌面窗口执行并记录启动、端口刷新、打开、发送、接收、关闭等关键交互验收。
- 在用户授权的真实设备上，以非控制性、可逆的探测报文执行并记录硬件串口验证。

## Non-goals

- 不向未明确识别、未授权或可能改变设备状态的端口发送数据。
- 不实现模拟下位机、独立窗口或宏编辑功能。
- 不将虚拟串口验证表述为真实设备验证。

## Acceptance

1. 可见 Electron 窗口显示已连接后端，并完成关键 UI 交互的视觉和行为证据。
2. 真实设备的设备标识、端口、串口参数、授权、探测报文与观察结果均记录；仅在安全前提成立时发送。
3. 若未发现或未获授权真实设备，证据明确为 `blocked`，不以虚拟端口替代。

## Risk tier

`L3` — 涉及桌面 IPC 安全边界和真实串口设备写入。真实发送必须满足设备、参数与操作授权的人工闸门。
