# Proposal: add-device-test-workbench

## Why

SerialScope 已具备收发、宏、规则、模拟下位机和日志，但这些能力彼此孤立，用户无法把一次设备通信验证保存为可重复、可判断、可交付的测试。

## What

- 新增“测试工作台”模块，以可视化节点图编排宏发送、串口读取、条件分支、循环与断言步骤。
- 宏节点引用现有宏；读取节点从 RX 序列等待匹配帧；条件节点按 HEX/文本/规则/变量比较选择下一条边；循环节点以显式最大次数和超时控制重复执行。
- 复用规则/HEX/文本匹配作为断言条件，复用模拟下位机作为对端场景。
- 执行后生成本地可保存的结构化报告，含时间、步骤结果、匹配帧和失败原因。
- 为首版提供一个可运行的 Modbus 读取示例用例。

## Non-goals

- 不实现通用脚本语言、云端协作或硬件资产管理。
- 不自动向真实设备执行用例；真实设备写入继续遵循 L3 授权。

## Acceptance

1. 用户可编排“宏写入 → 读取匹配 → 条件判断 → 宏写入”的流程，并保存、重载和执行。
2. 用户可配置受限循环；达到最大次数、超时、断言失败或手动取消时必须停止后续写入。
3. 成功、分支、超时、循环耗尽和断言失败均产生可辨识的步骤结果与报告。
4. 通过 COM10/COM11 + 模拟下位机的生产 Electron 自动化覆盖成功与失败路径。

## Risk tier

`L2` — 新增跨模块用户可见行为与持久化模型；默认不改变自动发送或真实设备写入边界。真实设备实际执行升级为 L3。
