# Design: add-device-test-workbench

## Decisions

| 决定 | 选择 | 理由 |
| --- | --- | --- |
| 用例模型 | React Flow 节点与边持久化为 JSON 图；节点类型为 `start`、`macro`、`read`、`condition`、`loop`、`assert`、`end` | 直接对应用户画布，不引入不可控的通用脚本语言。 |
| 宏节点 | `macro` 引用现有宏 ID，并在执行报告中保存宏 payload 快照 | 宏编辑仍是一处来源，流程可复现。 |
| 接收关联 | `read` 从用例启动后的 RX 序列等待匹配帧并写入变量 | 对单主机设备联调保守、可解释；规约级关联后续扩展。 |
| 条件与分支 | `condition` 用 HEX/文本/规则/变量比较选择带条件标签的出边 | 支持“读到特定数据才写下一条宏”。 |
| 循环 | `loop` 使用显式计数器、最大次数、最长耗时与可选退避延迟 | 防止无条件循环向串口持续写入。 |
| 断言 | HEX 精确/掩码、文本包含、规则命中、变量比较、超时 | 覆盖常见现场验收，同时保持 UI 可理解。 |
| 报告 | 本地 JSON + 可导出 HTML/CSV 摘要 | 可用于缺陷复现和交付，先不依赖服务端。 |

## Risks and mitigations

| 风险 | 缓解或验证方式 |
| --- | --- |
| 用例对真实设备产生副作用 | 默认仅在用户明确执行后发送；真实设备仍要求 L3 授权。 |
| 多条并发 RX 难关联 | 首版每串口一次仅运行一个用例，并展示所消费帧。 |
| 现有宏/模拟器配置冲突 | 用例执行快照配置；报告记录宏版本与模拟器状态。 |
| 循环误配造成持续写入 | 画布校验要求循环上限和超时；执行器支持取消，并在违反限制时失败停止。 |

## Out of scope

可编程 DSL、并行用例、远程设备农场及规约解析插件市场。
# 补充：双实例模拟回归

工作台的“启动第二个模拟实例”不复用当前进程的单一 `SerialSession`：它以 `--module=simulator` 启动新的 Electron/Main/Named Pipe 后端，并将内置 Modbus 配置以 base64url 参数传给模拟窗口。推荐配对为工作台 COM11、模拟实例 COM10。主实例与子实例均通过 `ports.list` 校验 COM10 的描述/厂商含有 `ELTIMA`、`VIRTUAL`、`SERIAL` 后才允许自动开口和自动应答；任何验证失败均拒绝启动或拒绝应答。工作台 Main 授权器只允许 simulation 目标写入 COM10/COM11，真实设备仍走单次原生确认。

父实例跟踪单一子进程、接收其自动开口结果并在工作台关闭时终止；Preload 缓存 bootstrap 消息避免渲染器异步订阅漏收。该能力的自动化范围目前只覆盖配置/流程执行器与虚拟 COM 原生应答器；双 Electron 实例的启动、配对占用和完整回归仍是后续验收项。
