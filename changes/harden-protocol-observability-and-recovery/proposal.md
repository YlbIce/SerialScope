# Proposal: harden-protocol-observability-and-recovery

## Why

现有原生测试已证明基本 COM10/COM11 收发，但未把 `serial.open → send → rx/tx → close → reopen` 作为一个完整可诊断的协议生命周期验证。Main、Renderer 和 C++ 后端仅写入各自控制台，崩溃或异常断开后无法按时间线关联；前端只能重连后端进程，不能按用户选择重试串口打开。接近 1 Mbps 和 128 KiB 以上帧的负载也缺少可重复基线。

## What

- 增加 JSONL 轮转诊断日志：Main 记录子进程、IPC、RPC 和渲染进程故障；Renderer 报告未捕获错误；C++ 后端记录请求、串口状态与收发事件，并以关联 ID 关联同一后端实例。
- 提供 opt-in 的串口自动重连：用户主动启用后，打开失败或意外关闭按有界指数退避重试；手动关闭/禁用会取消重试。
- 新增协议生命周期集成测试及虚拟串口大流量/长帧压测，覆盖可恢复错误、准确统计与有界事件交付。

## Non-goals

- 不在本 change 中执行真实物理设备写入或跨 Windows 会话实测。
- 不签名、发布或配置生产自动更新通道；这些属于后续 L3 发布闸门。

## Acceptance

1. 同一运行实例的 Main、Renderer 和后端诊断记录可按 `runId`/时间排序关联，单个日志文件超过上限会轮转且保留数量有界。
2. 启用自动重连后，串口打开失败会以指数退避重试；手动关闭不会继续重试。
3. 虚拟串口协议测试验证 open/send/rx/tx/close/reopen、错误输入与状态/统计；压测验证长帧与高频帧的有界结果。

## Risk tier

`L2` — 改变可观察的连接恢复和诊断持久化行为，并扩展跨模块 RPC/串口测试；不改变真实设备写入授权边界。
