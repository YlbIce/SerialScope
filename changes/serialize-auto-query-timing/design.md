# Design: serialize-auto-query-timing

## Decisions

| 决定 | 选择 | 理由 |
| --- | --- | --- |
| 查询调度 | `setTimeout` 链式调度，而不是 `setInterval` | 前一轮完成前不创建下一轮 RPC 请求。 |
| 完成条件 | 发送后第一条完整 RX 帧，或可配置超时 | 泛型串口工具没有统一关联字段；此规则对单主机轮询可验证且保守。 |
| 周期语义 | 周期为发送开始到下一轮的最小间隔，最小 10 ms | 保留高频配置表达能力，但实际速率受应答和超时限制。 |
| 观测 | 毫秒时间、单调日志序号、查询状态/在途数 | CSV 不再只能按秒推断乱序。 |

## Risks and mitigations

| 风险 | 缓解或验证方式 |
| --- | --- |
| 无关 RX 被视为应答 | 仅声明单主机轮询语义；后续规约关联另行设计。 |
| 设备不应答 | 每轮超时后才继续，记录超时，不积压 RPC。 |
| 10 ms 超过串口/设备能力 | 单在途形成反压；状态明确展示实际等待或超时。 |
| 真实设备副作用 | 本 change 不进行真实设备写入，只执行 COM10/COM11 虚拟验证。 |

## Out of scope

多主机总线仲裁、特定 Modbus 地址/功能码关联，以及真实硬件串口验收。
